# EnjoySA demo 可写联网 AI 执行器与 Fine Dining 草稿补全 PRD

## 1. 概述

### 1.1 背景

EnjoySA demo 的 Fine Dining 草稿补全需要执行器完成代码修改、联网、图片、数据库、上传目录、demo 部署与验证。此前 backend-au 以只读且禁网环境启动，流程无法闭环。当前已验证 workspace-write 和经授权的 demo SSH 访问。

### 1.2 目标

- 业务目标：AI 闭环完成五条 demo 草稿，减少人工导入与部署。
- 用户目标：审核人员在 demo 看到内容完整、带封面、仍为 Draft 的五个目标产品。
- 技术目标：具备工作区、联网、demo 数据库、持久化 uploads 和部署脚本访问能力，同时隔离生产。

## 5. 技术要求

### 5.1 性能要求

- 五条导入 60 秒内完成。
- 单事务，失败无半成品。
- JPEG 单张小于 500KB，长边不超过 1200px。

### 5.2 安全要求

- 不输出密码、JWT 或 API 密钥。
- 只访问 demo。
- 不 reset/seed 数据库。
- 生产部署须审批。
- 不复用未确认授权的官网图片。

### 5.3 兼容性要求

Go 1.24+、PostgreSQL 16、现有 `/uploads` 静态路由；重复导入结果一致。

## 7. 验收标准

### AC1: 执行器权限

**目标**：工作区可写且可访问 demo。

**VP-Data**：本地 cwd 与 `enjoysa-demo`；shell/SSH 只读检查。

**VP-Steps**：`pwd`；检查写权限；SSH `docker compose ps`；容器内只读 SQL。

**VP-Pass**：✅ cwd 精确、服务 healthy、SQL 返回产品；❌ 仅配置推断不通过。

### AC2: 精确五条

**目标**：仅目标产品。

**VP-Data**：localhost seeds；Go 测试。

**VP-Steps**：运行 `go test ./cmd/import-restaurant-botanic`；比较白名单。

**VP-Pass**：✅ 精确五条且无排除项；❌ 多或少均失败。

### AC3: 内容完整且 Draft

**目标**：双语、价格、套餐、元数据完整且保持 draft。

**VP-Data**：demo 目标 IDs；容器内 importer。

**VP-Steps**：运行导入；SQL 查字段/套餐/metadata；重跑复查。

**VP-Pass**：✅ 五条均 draft、关键字段完整、重跑无重复；❌ 发布或空字段失败。

### AC4: 原创封面

**目标**：每条目标产品一个 cover。

**VP-Data**：demo 五张 JPEG 与 `product_images`。

**VP-Steps**：SQL 查 `image_count/is_cover`；HTTP 请求五个 uploads URL。

**VP-Pass**：✅ 各一个 cover 且 URL 返回 200 `image/jpeg`；❌ 外链依赖或 404 失败。

### AC5: Demo 健康

**目标**：部署后页面和后端健康。

**VP-Data**：demo 五条草稿。

**VP-Steps**：部署；查 `/health`；Admin 检查草稿内容与封面；检查页面无白屏。

**VP-Pass**：✅ homepage、health 200 且五条可审核；❌ 健康/图片/范围失败。

### AC6: 生产隔离

**目标**：生产不变。

**VP-Data**：部署日志与目标主机。

**VP-Steps**：审查命令仅指向 `demo.enjoysau.com/enjoysa-demo`。

**VP-Pass**：✅ 仅 demo；❌ 任一生产写入失败。
